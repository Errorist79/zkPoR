The consent of every reserve address

This file holds two things and they are not the same kind of thing. The first
part is evidence: it reads back the record that a real registration wrote, and
it shows the answer the registry gives to any attempt to register that asset
again. The second part is a demonstration: it runs the consent flow against an
asset that nobody registered, so a reader can see what the act of signing looks
like and can run it themselves.

The acts of the real registration were not captured when it ran. That is why the
second part exists. It is the same flow, and it is not a record of what happened.

PART TWO, DEMONSTRATION. The same flow, against an unregistered asset.

The registry accepts an asset only when every reserve address signs its own
entry. The command line collects a signer for a top level address argument only,
and a reserve address sits inside a vector, so the flow has three steps. One
command builds the call and exports one entry for each address. Each address
signs its own entry, on its own machine if it wants to. One command reassembles
the whole and sends it.

The steps below are the first two. Nothing here sends a transaction, so no
registration happens and the asset stays unregistered.

The asset is DEMOSHARE, issued by GCJUJ3IGBAARLLEGMVVIZASHZQAMYGOVUN7JNEFECFB7PAZELIA3TDMD.
A classic asset needs no deployed contract for this, because its contract
address is a derivation of the asset. The address is CB5YTXY6TSSKY43UURQYP2LPODCJQYEU3GAFEZNNVZN4TY7AKUKJRK5F.
