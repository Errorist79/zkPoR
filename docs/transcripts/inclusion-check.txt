The customer inclusion check, when it holds and when it fails

A customer package names one balance, the salt of that leaf, and the path from
the leaf to the root. The check recomputes the root from those values and
compares it with the root that the registry attests.

The first check reads a package that the attestation run produced. The second
reads a copy of the same package with one digit changed in the balance. The
recomputed root then differs from the attested root, and the check answers
root-mismatch with the exit code 7.

The exit code is the verdict. 0 is included and 7 is a root that does not match.
Both commands read. Neither one sends a transaction.

How to read this file. A line that starts with `$` is a command, and every line
under it is what that command printed. A line that starts with `note:` is this
file speaking and no command printed it.
